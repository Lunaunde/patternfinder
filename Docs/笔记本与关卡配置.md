# Level、Puzzle 与笔记本拼接

开发继续使用 `chatgpt-dev`。当前示例以忍冬藤调试；本阶段提供拼接、配对与编辑基础，尚未实现完整关卡推进和知识卡解锁。

## 场景组织

`Scenes/main.tscn` 负责相机、花园操作、拍照流程及笔记本切换。Inspector 中的 `LevelScene` 指向当前关卡，`NotebookScene` 指向笔记本模板。

可复用模板放在 `Scenes/base`：

- `level.tscn`：空 Level，包含 Background、Patterns、Puzzle。
- `background.tscn`：背景控件，通过 `BackgroundTexture` 设置贴图。
- `pattern_object.tscn`：可识别原型，`Variants` 设置可拍摄纹样。
- `puzzle.tscn`：空 Puzzle，包含 PuzzleBases 和 PuzzleBlocks 两个容器。
- `puzzle_base.tscn`：纯视觉底座，可设置 Sprite2D 的 Texture；不参与正确判断。
- `puzzle_block.tscn`：可手动摆放的目标模板，目标贴图只在编辑器中显示。
- `notebook.tscn`：笔记本外观和拼图操作界面。

实际调试内容放在 `Scenes/levels/honeysuckle.tscn` 与 `honeysucklePuzzle.tscn`。`Scenes/frame.tscn` 保持原位置；素材栏由 `Bar.cs` 创建。根目录中未使用的 Background、PatternObject 和 Bar 旧场景已清理，原文件备份于 `Output/scene-cleanup/unused-scenes-20261006-182139.zip`。

## 素材 ID 的作用域

每个 Level 包含自己的素材目录、库存、原型和 Puzzle。不同 Level 可以使用相同的 MaterialId。

在同一 Level 内，PatternVariant 的 `MaterialId` 与 PuzzleBlock 的 `MaterialId` 相同，表示可以用该原型产生的纹样配对这个目标。多个目标可以使用同一 ID，例如重复的忍冬单元。

Pattern 的 Variants 指定素材卡和新生成碎片的源贴图；PuzzleBlock 的 Texture 用于编辑器目标图，并在配对成功时作为目标外观应用到碎片，允许二者采用不同的美术版本。匹配依据 ID、位置和角度，不依赖贴图引用相同。

每个 `PatternVariant` 新增 `Scale`，默认 `(1,1)`。新生成碎片的 Puzzle 本地宽高为 `MaterialTexture.GetSize() × abs(Scale)`；该值独立于花园中 PatternObject 节点的 Scale，不再自动取第一个同 ID 目标的 Scale，也不再自动压到最长边 220。当前忍冬源图为 1766×1757，`Variants.Scale=(0.25,0.25)` 对应 441.5×439.25 本地单位，与现有两块目标的 0.25 比例一致。

拍照时将 Scale 与 ID、名称、Texture 一起冻结并存入库存；后续修改 Resource 不会改掉已收集卡片的默认大小。从卡片拖出的预览与落地碎片使用同一份 Scale，屏幕显示再乘笔记本和 UI 的布局缩放。卡片中的缩略图仍适配固定展示窗口。非等比 Scale 保留两轴比例，负数表示对应轴镜像；零、NaN 和无穷比例不参与有效素材选择或入库。

Scale 表示默认生成尺寸。匹配成功后仍采用实际目标的贴图、Scale、Offset、Centered 和 Flip 配置，并吸附位置、角度；移动已经匹配的碎片时保留该目标外观，延续原有行为。

从库存拖入时，笔记本同时验证来源 Level 和库存条目对象，防止另一个 Level 的同名 ID 被当作本关素材。生成后的碎片独立保留，库存卡的删除不会反向删除页面中的已有碎片。

## 手工制作 Puzzle

1. 复制空 Puzzle 模板制作自己的拼图场景，或复制忍冬示例进行调整。
   在 PuzzleBases 下实例化一个或多个 `puzzle_base.tscn` 并设置 Texture、位置、旋转和缩放。这些纯视觉底座会复制到笔记本页面，保持每层变换与显隐设置，不参与素材 ID 配对；旧的 Puzzle 根下单个 PuzzleBase 仍兼容。
2. 在 PuzzleBlocks 下实例化若干 `puzzle_block.tscn`。
3. 为每块设置 MaterialId 和 Texture，并在 Godot 2D 编辑器中移动、旋转、缩放，拼成目标图案。Texture 可直接使用 PNG 或 AtlasTexture。
4. 使用 Puzzle 下的 `NotebookPreview` 作为编辑器定位图。它使用与实际笔记本相同的手账贴图，以 Puzzle 的 `(0,0)` 为书本中心，当前宽度为 1320、本地范围约为 `(-660,-514)` 到 `(660,514)`。将 PuzzleBlock 直接摆在这张图上；位置按 Puzzle 本地坐标计量，碎片中心对应 PuzzleBlock 中心。建议保持 Sprite2D 的 Centered 开启、Offset 为零。
5. 在 Puzzle 的 Definition 中创建 `PuzzleDefinition` Resource，设置统一的 `PositionTolerance` 与 `AngleToleranceDegrees`。
6. 每个 PuzzleBlock 默认启用 `UsePuzzleDefinition`。关闭后使用该块自己的 PositionTolerance 与 AngleToleranceDegrees。
7. 将该 Puzzle 场景作为 Level 的 Puzzle 子节点；把相关原型放入 Patterns 容器，并在 Variants 中填写对应 ID。

位置容差采用距离，单位是 Puzzle 本地单位，不受屏幕缩放影响；角度容差使用度数，并按最短环绕角度差计算。无效或负数容差不参与匹配。同 ID 有多个目标时，选择容差内最近且未被占用的目标。目标的 Offset、Centered、FlipH/FlipV 和负缩放也会传给匹配后的碎片，保持编辑器中的视觉配置。

`NotebookPreview` 与 PuzzleBlock 都是编辑器定位数据，运行时隐藏，但它们的 Texture、MaterialId、位置和角度继续参与正确判断和配对后的外观配置。可在编辑器中按需要切换 Level 下 Puzzle 的 Visible；进入游戏后由 `Level._Ready` 隐藏源 Puzzle 配置。PuzzleBoard 复制 PuzzleBases 容器下的底座（也兼容旧单个 PuzzleBase），源 Puzzle 父节点的隐藏不影响页面底座；页面只保留底座本身设置的 Visible。定位图或 PuzzleBlock 即使被放在底座内也会被排除，玩家打开笔记本时看到的是书本、配置的底座和实际放置的碎片。

笔记本在 2430×1080 的设计区域内使用 `Rect2(555,26,1320,1028)`；书图与 Board 占用相同区域，Board 的 `PuzzleScale=1`，Puzzle 本地原点对应设计坐标 `(1215,540)`。因此编辑器中相对定位图中心的坐标，对应运行时相对 Board 中心的坐标。窗口比例变化时，既有 AspectRatioContainer 仍按 2.25 的设计比例居中、等比缩放，不用按真实屏幕像素重做目标坐标。

## 文案与状态数据

NotebookUI 的 `Content` 在 Inspector 中引用 `NotebookContent` Resource，保留 `Title`、`Instructions`、`DeletePrompt`、`DeleteHoverPrompt`、`BackLabel`、`DeleteSelectionLabel` 六个文案字段。周围的标题、说明、进度和删除提示不再生成 Label；关闭按钮通过原生 Line2D 绘制 `×`，白区中的删除选中按钮只绘制图标。

当前标题和状态可读取 `ResolvedTitle`、`CurrentDeletePrompt`、`PlacedCount`、`MatchedCount`、`TargetCount`、`IsDeleteHovered`。这些数据仍随页面和删除 hover 更新，后续可以重新用于知识界面或无障碍说明，不需要从 UI 节点取文字。

## 操作

- 松开取景后，点击右侧笔记本图标打开；点击 `×` 或按 Escape 返回。
- 素材栏保持在屏幕下方，通过右上角箭头折叠、展开；仍可左右拖动浏览、在卡片之间插入排序。素材栏使用 ZIndex 10，在笔记本上方绘制和接收输入。进入笔记本时展开，返回花园时恢复进入前的花园展开状态。
- 素材栏背景使用 `Assets/Texture/gardern/garden_cardbar_bg_open_extend@3x.png` 与 `garden_cardbar_bg_close_extend@3x.png`，两张图片均为 1545×480。背景顶部仍对齐原位置，新增部分只向下延伸，超出视口的部分自然裁剪；展开/收起定位仍按原有 276/105 高度计算，卡片和按钮坐标保持原样。
- 素材栏只生成库存中已有的卡片。未收集的卡位不显示半透明卡框、纹样或编号；删掉最后一张卡后，素材栏为空，仍可收起和重新收集。
- 长按素材卡，或上下拖出卡片，纹样跟随指针。放到笔记本纸面上，在松手位置生成一个碎片；原卡保持原位、库存数量不变。
- 同一张素材卡可重复生成多个碎片。拖到纸面外松手或取消手势时，卡片返回原位，不生成碎片。
- 拖动纸面中的碎片可移动。正确 ID 且落在位置、角度容差内时，会对齐对应目标并显示绿色描边。
- 本阶段已匹配碎片仍可移动和删除，移走后释放目标位置，供其他碎片匹配。
- 将碎片拖到右侧白色区域，区域变色后松手删除；也可点击白区中的垃圾桶图标，或按 Delete/Backspace 删除选中碎片。白区不显示文字，删除碎片不删除素材卡。
- 关闭笔记本再打开，会保留本 Level 的碎片和位置。切换显示另一 Level 时，其页面状态独立。
- 失焦、窗口缩放、触摸取消、关闭笔记本都会取消正在进行的拖动，恢复碎片原位置。
- 花园中的素材卡删除、排序、向左插入动画、Frame 的 Detected 和 FrameInsideRate 规则保留。

当前页面状态与素材库存均为运行期状态；退出后的磁盘存档、旋转/翻转按钮、翻页、知识展示与完整第一关解锁流程继续留作后续工作。

## 帧率候选设置

本轮将 `application/run/max_fps` 设置为 60，Android 的 `enable_frame_pacing=true`、`swappy_mode=0` 作为对照候选。[Godot 4.7.2 Vulkan 源码](https://github.com/godotengine/godot/blob/4.7.2-stable/drivers/vulkan/rendering_device_driver_vulkan.cpp#L3506)中 mode 0/2 对 SwappyAuto 接口的调用与[文档语义](https://docs.godotengine.org/en/stable/classes/class_projectsettings.html#class-projectsettings-property-display-window-frame-pacing-android-swappy-mode)有差异，本次设置没有在手机上验证。当前不能据此判断已解决 30 FPS，也不能判断已关闭自动帧率调整；需要在实际手机上对照记录帧率和帧时间。
